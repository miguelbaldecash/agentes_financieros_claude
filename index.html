7/10 KYC Screener — Analisis Profundo con OCR

Que hace (v6 — version final)

Cruza 2 DBs, analiza 2,128 documentos OCR de 341 personas. Detecta patrones anomalos entre solicitudes del mismo cliente: variacion de sueldo, cambio de empleador, documentos a nombre de terceros.

17 reglas de deteccion
Cross-solicitud (OCR profundo) — R1-R8
R1Sueldo varia >30%/50%/100%1/2/3 pts
R2Empleadores distintos en boletas (2/3+)2/3 pts
R3Nombres en docs != solicitante (1/2+)2/4 pts
R4DNI en doc OCR != DNI solicitante3 pts
R5Boletas OCR vs sueldo declarado (>50%)2 pts
R6RCI en documento OCR >40%2 pts
R7Equifax score OCR <400/<5002/1 pts
R8Multiples RUCs empleador (2/3+)1/2 pts
Individual — R9-R14
R9Ratio rechazo >70% / exceso sols 8+2/1 pts
R10Edad <19 / <202/1 pts
R11Score <250/<350 / sin score2/1/1 pts
R12Sueldo =0 / <8002/1 pts
R13Sin Equifax / Keynua err / DNI mis / sin arbol1/2/3/1 pts
R14Edad varia >3 anos entre solicitudes1 pts
Anti-fraude — R15-R17 (0 disparos en esta muestra *)
R15Distinto apoderado entre solicitudes (2/3+)2/4 pts
R16Apoderado compartido con otros solicitantes1/3 pts
R17Correo compartido con otro DNI2 pts

* R15-R17 existen en la base general pero no en este segmento (solo cupon + OCR). Clasificacion: BAJO pts<=2, MEDIO 3-4, ALTO >4.

Desestimado Pitch Agent

Que hace

Genera pitch decks y materiales para inversores extrayendo data directamente de la DB. Produce un pitch narrativo (.md) y un deck visual (.html) con graficos interactivos.

Output generado
Pitch narrativoPITCH_BALDECASH_2026.md
Deck visualPITCH_BALDECASH_2026.html (10 slides)
ContenidoExecutive summary, mercado, traccion, NPL, financieros, fondeo, valorizacion, riesgos
Por que se desestimo

El output es tecnicamente correcto pero un pitch para inversores requiere narrativa estrategica, contexto de mercado, y posicionamiento que solo el fundador puede definir. El agente es util como base de datos pero no como autor del pitch.

Conclusiones y Proximos Pasos

Recomendacion

Implementar: KYC Screener (7/10)

17 reglas sobre 341 solicitudes y 2,124 docs OCR. R1-R8 detectan anomalias cross-solicitud, R9-R14 evaluan perfil individual, R15-R17 detectan fraude (apoderado/correo compartido — validados en base general pero 0 disparos en esta muestra de cupon). Para 9/10:

  • Correr R15-R17 sobre base sin filtro de cupon (donde si existen los patrones)
  • Ampliar a 1,000+ casos para calibrar thresholds con regresion logistica
  • Cruzar RUC de empleador en boleta vs SUNAT (empresa activa/habida)
  • Integrar las 17 reglas en flujo pre-desembolso automatizado

Evaluar: Statement Auditor + Valuation (4/10)

Utiles como herramientas internas, pero limitados por la calidad de la data contable. Recomendable re-correr despues de la remediacion contable (90 dias).
